An agent in Quilzo is a declaration: what it is for, which capabilities it has, what it may read, how far it may go on its own, and how much one run may spend. A model or a program decides each step. The declaration decides what is allowed, and a hijacked agent still cannot do anything the declaration does not list.

Declare an agent

  1. Start from a template

    Open Administration › Agents, which opens to whoever holds manage-agents on the agents, not only to administrators. Under Start from a template, pick the archetype closest to what you want. Each one starts with as little permission as it needs, and you add only what is missing. Most agents are retrieval: they answer from published content and cannot write.

  2. Fill in the declaration, or describe it

    The Declare an agent form has a section for each part of the declaration: what it is for, what it may read, what it may do, which other agents it may hand work to, what it remembers between runs, how far it may go on its own, and how much one run may spend. A banner at the top says, as you go, whether the declaration as it stands would be accepted.

    If a model is connected, you can open Describe it instead, describe the agent in a sentence, and press Draft it. The model drafts a declaration, Quilzo keeps only the fields a declaration has, and the checker shows what the draft could do before anything is saved. A draft never adds tools or the ability to publish: the screen lists what it left out, and only a person can add those.

  3. Mark what must wait for a person

    Under What it may do, tick ask first beside any capability that should stop the run until a person agrees. For an agent that edits pages, that is write_page.

  4. Check the map, then save

    The map under What it reads, and what it may do is drawn from the declaration itself, so the two cannot disagree. Capabilities that ask first are highlighted. Press Declare it.

The same thing as a file

A declaration is one JSON document, so it can be reviewed and kept in version control. quilzo agent new NAME --kind KIND creates one from a template. To declare one written out, save it to a file and pass it to quilzo agent declare, which validates it on the way in:

{
  "name": "returns-editor",
  "kind": "task",
  "purpose": "Keep the Returns and Delivery pages accurate, asking before each change",
  "capabilities": ["list_pages", "read_page", "search_pages", "write_page"],
  "autonomy": "draft",
  "ask_first": ["write_page"],
  "budget": { "steps": 25, "tool_calls": 15, "duration": "10m0s", "money": "0.50" }
}
quilzo agent declare returns-editor.json
quilzo agent show returns-editor --json      # what is saved, as JSON
quilzo agent check                           # does every declaration still validate

Two fields are optional. instructions says how the agent should work, as a system prompt did elsewhere: it goes to the model with every decision, after the operations and the rules, which still decide what can be done. model names the model it prefers: a run tries the gateway route serving that model, or named so, first, and the others after it. Both are on the agent's page, under How it should work and Model.

Bring an agent from another platform

An agent built elsewhere comes in as a declaration, with a report of what was kept, what was changed to work here, what was left out and what is yours to decide. Under Agents, choose Import one from another platform, choose the file or paste it, and read the report; then declare the ones you tick. Or:

quilzo agent import .claude/agents/code-reviewer.md     # read it; nothing is declared
quilzo agent import agents.yaml --save                  # declare what checks, a team's helpers first
quilzo agent import bedrock-agent.json -o imported/     # write it out, to change before declaring
quilzo agent formats                                    # what is read and what is written

The format is recognised from the file, and --from names it when it cannot be. Instructions, the model, the helpers an agent hands work to and its step and time limits carry over as they were. Read, search and file tools become the capabilities that do the same here. An API an agent called through an OpenAPI schema becomes tools on that host, the operations that write asked about first, with the schema written beside it for quilzo integrations import.

A code interpreter becomes code_run: Python in a workspace of its own, with no network. Other code another platform ran for the agent (a Python tool, a Lambda), a shell, MCP servers and other platforms' data sources become decisions, because here nothing is reached that the declaration does not name. Whatever it was allowed elsewhere, an imported agent starts at propose, or draft if it writes, until you give it more. An agent another vendor runs and offers by an A2A card is registered rather than imported (see Fleet).

To take one the other way, open the agent and choose Take it to another platform, or run quilzo agent export returns-editor --to claude-subagent. The file is printed alone, and what the format has no field for (the budget, autonomy, asking first, which pages it reads) is listed beside it rather than lost without a word.

Run it

On the agent's page, under Try it, write what it should do and press Run it once. Tick Let a model choose the actions to have a model decide. Leave it unticked to try every capability once without a model, which costs nothing and shows what this store answers. From the command line:

quilzo agent run --model returns-editor "Explain on the Returns page how to start a return"

A run never has more authority than the person who started it, and never more than the declaration allows. When it finishes it says what the agent concluded, after its steps; with --json, quilzo agent run prints the run's record instead, the one quilzo agent trace RUN --json shows.

What a run can do is what quilzo agent capabilities lists, by where it happens: the pages, which the run reads and writes itself; the reads the agent interface offers, and the writes there that make a draft or a proposal, done as the person the run is for; its memory, browser, workspace, the web and a desktop cell. A declaration naming anything else, such as one of an administrator's reports, is refused when it is saved rather than failing the day the agent runs:

snoop asks for the capability "shield_status", which nothing an agent runs performs (quilzo agent capabilities lists what does)

A decide step asks a decider about a state, which may be text, an object or a list, such as a ticket with its fields; an object or a list goes to the decider as text, its keys in order, fenced as untrusted like any other. The agent commands take their flags on either side of the file or the name: quilzo agent declare FILE --widen and quilzo agent declare --widen FILE are the same.

A new agent driven by a model starts at propose. Quilzo lets a model drive an agent at its declared autonomy only after evaluations show the model is not steered by instructions planted in what it reads. Drafting takes at least three evaluation cases, each run three times. Until then, the run says a model drives returns-editor at propose rather than draft and explains why. Evaluate an agent shows how.

Approve or decline what it asks for

When the run reaches a capability marked ask first, it stops. The run's page shows the exact call it wants to make, field by field, with the full JSON one click away, and says what it had read before asking.

  • Let it go ahead performs exactly the stored call, through the same limits as everything else. The model is not asked again, so it cannot change the call after you agreed to it.
  • Decline refuses it, and the run carries on without it.
quilzo agent approve RUN 3
quilzo agent decline RUN 3

The agent's sponsor decides, as does whoever holds the approve permission on the agent or on the page it would change (see who approves an agent's actions). A model cannot approve its own work, declare an agent, or widen one. What an agent writes is a draft: it goes live only when somebody publishes (see Review, publish and roll back).

Everything waiting, in one place

What waits on a person is one list. Approvals lists everything waiting for you to decide: what agent runs are asking, questions they need answered, actions the reviewer stopped, tool calls held for a second person, the change to the site waiting for approvals, features waiting to be installed and features agents drafted, newsletter issues agents proposed, and memories held until somebody confirms them. Today and quilzo approvals hold the same items. Each says what deciding commits to: reads, acts, writes, sends, pays, deletes, publishes, installs or answers. quilzo approvals gives the command that decides each.

Staff are told when an agent starts waiting: approval.waiting is in notify.events by default. The notice says which agent is waiting, never what it would do, and deciding is done signed in, under Approvals (see Telling staff).

When several runs wait on the same action, with the same input and the same reason, and the action only reads or acts, Let all go ahead approves them together. Anything that writes, sends, pays, deletes or publishes, and every question, is decided on its own page.

Questions it cannot answer alone

An agent that asks a decider a question, and gets an answer less sure than the decider requires, stops and asks a person instead. The run's page shows the question in its own shape, a list of options, yes or no, or a number from 0 to 1, with the model's guess and how sure it was. The run continues with your answer and never with the unsure one. What the decider did settle is kept: the step's result names your answers, then each one the decider settled, with how sure it was.

quilzo agent answer RUN STEP eligible=no

When the store names a reviewer and it refuses an action, the run stops on that action. Let it go ahead performs exactly that action without asking either model again.

Read what it did

Every run is kept, step by step, as it happens: what it tried, whether that was allowed, how long it took, and what came back. If it read content somebody else could have written, the run says so, names what it read, and its output needs a person before anybody relies on it.

quilzo agent trace RUN ends with what the agent concluded, whether a model or its program decided, made printable first, since those words are the agent's to choose.

Each step records the tokens and money of the model's choice and of whatever the action charged, at the model gateway's prices, so a run's cost is the sum of its steps. The run's page shows it beside each step. What they cost groups the kept runs by agent, by who started them, by kind of goal or by day; numbers, addresses and quoted words are taken out of goals, so "Refund order 1234" and "Refund order 98" count as one kind of goal. A run a model decided with no price is shown as not priced rather than as free.

When it runs on its own

An agent can start without anybody pressing Run it once: at a time, or when something happens on the site. On the agent's page, under When it runs on its own, open Start it on its own, choose what starts it and what each run does, and press Add the trigger. Or:

quilzo agent trigger gardener add --every 24h --at 07:30 --zone Europe/London \
  --goal "Check the planting calendar against the frost dates"
quilzo agent trigger gardener add --on page.published --where /guides \
  --per-day 6 --goal "Propose links to the new care guide"
quilzo agent trigger gardener          # what starts it, and how many runs today
quilzo agent trigger gardener remove 2

A schedule repeats every 15 minutes at the most often. With --at it repeats in whole days, at that time in the zone given (UTC when none), and keeps that time when the clocks change. quilzo agent trigger events lists the events:

To start it whenAdd

A draft is proposed for review--on draft.proposed
Records in a collection change--on record.changed
Somebody sends a form--on form.submitted

Somebody joins the newsletter, or leaves it--on subscriber.joined, subscriber.left

A chatbot cannot answer a question--on chatbot.unanswered

--where narrows an event to what it is about: a page path and everything under it, a collection, a form, a chatbot or a service. What started a run is given to it after its goal, as data and not as instructions.

  • Each run is its sponsor's, checked when it starts: an agent nobody answers for, or whose sponsor may no longer run it, does not start. It is capped at drafting and proposing whatever its sponsor holds, so publishing, and anything that goes out, is still a person's decision. It needs a model to decide with, since a run nobody asked for does not walk its declaration blind.
  • It does not run away. A trigger starts at most its day's runs (24 unless --per-day says otherwise, up to 500), never a second while one is still going, and never from something its own agent did. A chain of agents starting one another stops at three.
  • The admin server starts them. quilzo serve runs at most two triggered runs at once (agents.trigger_runs). agents.triggers turns triggers off for the store: nothing starts unless a person runs it, and turning them on again starts nothing for what happened meanwhile.

How far an agent may go on its own

AutonomyWhat happens to what it writes
proposeIt suggests, and a person does it.
draftIt writes drafts, which nobody is served until a person publishes.
publishWhat it writes goes live.

The autonomy you declare is a ceiling. A model reaches it only by passing evaluations, and loses it the moment it follows a planted instruction (see Evaluate agents).
