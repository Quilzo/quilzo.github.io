Serve the content API

quilzo site --api                 # read-only, at /api/v1
quilzo site --api --api-writable  # PUT allowed; every write needs If-Match

A write must carry the version it was based on, so two writers cannot silently overwrite each other. Try it against your own store in Reference › API.

These are the public site's flags, and quilzo site --help lists them; quilzo serve has neither. The admin serves the same API read-only, for the playground. A write that a read-only API refuses names the fix: quilzo site --api --api-writable.

Both, the site's and the admin's, read the access rules again on every request when they have changed, so a grant made or taken away while they run counts at once. /api/v1/openapi.json describes every route as an OpenAPI 3.1 document, for a client generator or an agent. It is the same for every installation and needs no token; every route it describes does.

The command line

Everything the admin does, the command line does, through the same code. quilzo help lists every command. Each takes --json and then writes one JSON document to stdout, and --root DIR chooses the store.

Exit codeMeans
0Success
1Failed
2Misused
3Refused by a gate
4Not found
5A required dependency was missing

A gate refusing (3) is not the command failing (1). Branch on the code, not on the wording, which is free to improve. The command line finds its token in --token, then ~/.quilzo/token, then QUILZO_TOKEN.
