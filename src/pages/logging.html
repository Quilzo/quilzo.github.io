Identifiers are pseudonymised in the log, wherever a person appears: as who acted, in the resource, and in the text of a record, where a name is replaced by the same pseudonym. A secret that was refused is never written. Receipts for runs, apps and forgotten memory are built from it (see receipts), and it exports to a SIEM (see traces and the audit log).

Anchors and timestamps

An anchor commits a digest to the public OpenTimestamps calendars, which batch it into a Bitcoin block within hours; until then it is pending, which is not anchored. quilzo anchor submit sends the live commit of what is published, quilzo auditlog anchor the audit log's head, and each anchor says which it is of: a publication or the log's head.

  • A timestamp is over the full live commit too, the same digest an anchor of that publication commits to, so quilzo timestamp list and the Integrity screen show each timestamp with its publication's anchor.
  • Sending a digest out, by anchor submit, anchor upgrade or timestamp stamp, takes the grant permission and is on the record. Reading and exporting what is kept takes only view.
  • quilzo anchor export --dir DIR writes each proof as an .ots file; ots verify -d DIGEST FILE then checks the block it names against the chain, which Quilzo has no headers for.

When the log cannot be written

An agent does nothing it cannot record. Before each action an agent takes, Quilzo checks that the log can take its record: the log writer answers, the key can be read, more than 8 MiB is left where the log is kept, and the last record was written. If any of these fails, the action is refused and the run stops with the reason, which names the audit log. A step whose record was refused stops the run before its next action.

The same check refuses changes made over the agent interface, presses in a browser an outside agent drives, and tools forwarded to another system through the MCP gateway. Reading goes on. What a person does in the admin or on the command line goes ahead, and the failure is printed where they act; quilzo auditlog verify shows any gap afterwards.

Once the writer or the disk is fixed, the next record that is written clears the refusal.
