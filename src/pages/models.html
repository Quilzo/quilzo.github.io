The model gateway is where every model call from Quilzo goes: agents, chatbots, the writing assistant, analyst triage, and agents' own programs. It tries routes in order, charges each call to a caller at that route's prices, holds callers to their budgets, and masks personal data before a prompt reaches a route that may not receive it. Prompts are never recorded, only who asked, which route answered, and how much.

The quickest start: one model

With no routes declared, every call goes to the model in two environment variables. Any OpenAI-compatible endpoint works: Ollama, vLLM, LM Studio, llama.cpp, or a hosted provider.

export QUILZO_MODEL_URL=http://127.0.0.1:11434/v1
export QUILZO_MODEL=llama3.1

A key, if the endpoint needs one, goes in QUILZO_MODEL_KEY. Quilzo sends a key only over https, or to a model on this machine.

Add routes, in fallback order

  1. Add each model as a route

    Open Administration › Models and fill in Add a route: a name, the address, the model name, the environment variable holding its key (never the key itself), and what a million tokens cost there. Or:

    quilzo gateway currency GBP
quilzo gateway route add on-premises --url http://127.0.0.1:11434/v1 --model llama3.1 \
  --personal --price-in 0.05 --price-out 0.20 --first
quilzo gateway route add hosted --url https://models.example.com/v1 --model example-large \
  --key-env EXAMPLE_API_KEY --price-in 2.50 --price-out 10.00

    Mark a route --personal only if it may receive personal data: it runs on your own machines, or you have an agreement with the provider to process it.

  2. Check the order

    Routes are tried in the order shown. A route that fails three times in a row rests for a minute while the next one answers. Try first moves a route to the top.

  3. Set budgets

    Under Budgets, give a caller limits per minute, per day and per month: calls, characters, tokens and money. A caller is agent:NAME, person:NAME, chatbot:NAME, or * for everybody without a budget of their own.

    quilzo gateway budget agent:returns-editor --money-per-day 5.00 --money-per-month 60.00
quilzo gateway budget agent:concierge --per-minute 20 --tokens-per-day 200000
quilzo gateway budget '*' --money-per-day 20.00

    A chatbot over its daily budget answers from its pages without the model, which gives a plainer answer rather than an outage. Each agent run also has its own cap in its declaration (see Limits that hold).

  4. Watch what each caller spent

    Today shows every caller's characters, tokens, money, calls, failures and refusals, for the day and the month.

    quilzo gateway status
    routes, in fallback order
  on-premises  http://127.0.0.1:11434/v1 llama3.1  no key needed; may receive personal data
  hosted  https://models.example.com/v1 example-large  key in $EXAMPLE_API_KEY; personal data masked
today
  agent:returns-editor  4463 characters no daily limit, 3 call(s), 0 failed, 0 refused
    1112 tokens, 0.000067 GBP today of 5.00, 0.000067 this month of 60.00

The privacy guard

Before a prompt leaves for a route that may not receive personal data, Quilzo replaces each personal value with a placeholder such as <quilzo:email:1>. The same value gets the same placeholder every time, so the model can still tell one customer from another. The placeholders are swapped back in the answer, so it reads as if nothing was taken out. The model never sees a value, and the record of what was masked holds only counts by kind.

MaskedFor which routes
Email addresses (except your own site's domains), telephone numbers, IBANsRoutes not marked --personal
National identity numbers: US SSN, UK National Insurance, Spanish DNI and NIE, Indian Aadhaar, Brazilian CPF, Canadian SIN, each checked with its own rulesRoutes not marked --personal
Payment card numbers and credentials (API keys, tokens, private keys)Every route, including personal ones

A credential caught in a prompt is also a sign that a key was pasted somewhere it should not have been, so the shield's secret-in-prompt playbook opens a case for somebody to look at it and rotate it (see The shield). A hosted route allowed to receive personal data is a posture finding until an agreement is on record.

Invisible text never reaches a model

Characters that draw nothing, such as the Unicode tag block, zero-width characters and bidirectional controls, are taken out of every text before any model reads it. They are a known way to hide an instruction from the person reviewing a page while a model still reads it.
