1. Review what changed

    ToRun
    Who has agreedquilzo review status
    Agree to it (authors cannot)quilzo review approve --note "..."
    Require approvalsquilzo review require 2
    Require people, whoever wrote itquilzo config set approval.required_humans 2

    Approving takes the publish permission. A draft whose latest change a model made, over MCP, through the writing assistant or in an agent run, is held for a person on every surface: Publish to live on the Review screen, quilzo publish and the machine interface. It needs a person's approval whatever the number required, and the person whose agent run wrote it approves it only when nobody else may publish. Any draft waits for the number of people approval.required_humans asks for.

    While the approval policy cannot be read, nothing is published. The Approval card says The approval policy could not be read, so nothing is published from here, and the command line and the machine interface refuse as well.

    Approvals are checked on the commit being published, and a publish puts live exactly the commit its checks were asked about. A save that lands in the meantime is not published with it, and stays in the draft.

  2. Let the gates run

    Accessibility, provenance, claims that need substantiating, image rights and content scans stop a publish rather than warn. Each can be overridden with a reason, and the reason is recorded.

    quilzo scan also finds every kind of secret Quilzo makes, under the rule secret.quilzo-secret: the provisioning token, a Shared Signals push secret, an app's refresh token or authorization code, and an enrolment link's secret. Each finding says how to replace it. The accessibility check reports a link that opens a new tab without saying so (new-tab-not-announced) as advice, not as a block.

    quilzo a11y
quilzo provenance check
quilzo brand check
quilzo scan

  3. Publish

    quilzo publish

  4. Roll back if you need to

    Going back returns to a version that was live before, from Release › History, where each version's Status says live, was live (with Make live beside it) or never published, or from the command line. A version that was saved and never published is not offered: it goes live through Review, where it is checked.

    quilzo rollback --steps 1

Environments and scheduling

ToRun
Add a stagequilzo env add staging --before production
Promote: the same bytesquilzo env promote staging production
Comparequilzo env diff staging production
Publish laterquilzo schedule add 48h
Call it offquilzo schedule cancel ID
See what is scheduled and what firedquilzo schedule list

Promoting into production is a publish. Every check quilzo publish makes runs on the commit being promoted, and the promotion is recorded and announced as a publish is. It takes publish's options: --force-inaccessible or --force-unmarked with --reason, and --no-a11y-check. --skip goes past the environments in between, and the record says so. A promotion from Release › Publishing that a check stops opens the Review screen, whose button then reads Promote staging to production, so a reason given there promotes rather than publishing the draft.

quilzo serve publishes each scheduled entry within a second of its time, and at once if it fell due while the server was down, saying how late. With schedule.in_server off, a timer of your own runs quilzo schedule run instead; the two never publish one entry twice. An entry whose draft has moved since it was scheduled is not published.

A scheduled publish goes out on the authority of whoever scheduled it, checked when it fires, with the publisher role and no more, and every check of a publish runs then. The record names who fired it. Under Release › Publishing, Scheduled lists what fired in the last thirty days, and why anything was refused.
