Telling staff

Staff hear when somebody is waiting on them. notify.staff is where: mailto: addresses, or secret:NAME for a Slack, Teams or Discord incoming webhook sealed with quilzo secret set NAME. A webhook's address in the setting itself is refused, because whoever has it can post as the site.

ToRun
Mail the teamquilzo config set notify.staff mailto:team@example.org
Post to a chat channelquilzo secret set staff-hook < hook.txt, then quilzo config set notify.staff secret:staff-hook
Choose what they hear aboutquilzo config set notify.events ...; quilzo agent trigger events lists them

notify.events is handoff.requested,form.submitted,approval.waiting by default: a visitor asking for a person, a form sent, and an agent waiting for a person to approve. At most thirty notices go out an hour. A notice says which chatbot, form or agent and how many, never who or what they wrote. Mail goes through the relay in mail.json in the store (a store that kept it in notify/mail.json is still read), and a notice that could not be sent is a failure on the record.

Every connection, named

Each outbound connection has a declared purpose (models, integrations, connectors, webhooks, guardrail, fleet and others) and is checked against the address actually dialled, after DNS. Set network.mode to offline and every connection that would leave the host is refused before a packet is sent, naming the feature that wanted it; loopback still works, so a local model keeps working.
