Quilzo is a self-hosted control plane for AI agents. Each agent has a declaration saying what it may do, and one gate enforces it on every action. A person decides on the actions that matter, and every run is recorded in a signed log. It ships as a single program with no dependencies.

This guide takes about ten minutes. You need a terminal on Linux, macOS or Windows. A model is optional: an agent can walk its declaration without one, and you can connect a model at the end.

Install and sign in

  1. Get the program

    Download a release for your platform and check it. Releases are built for Linux, macOS and Windows, on amd64 and arm64.

    curl -LO https://github.com/Quilzo/Quilzo/releases/latest/download/quilzo-linux-amd64
curl -LO https://github.com/Quilzo/Quilzo/releases/latest/download/SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS
sudo install -m 0755 quilzo-linux-amd64 /usr/local/bin/quilzo

    Or build from source with Go 1.27. There are no third-party modules to download:

    git clone https://github.com/Quilzo/Quilzo && cd Quilzo
go build -o quilzo ./cmd/quilzo

    Released binaries trail main, so build from source if you want everything this manual describes. Install and run it for real covers checking a release's provenance, the container image, and running it as a service.

  2. Create a store

    A store is a directory holding everything Quilzo keeps: content, history, access policy, credentials, agents and the audit log. Back up that one directory and you have backed up everything.

    quilzo init
    created .quilzo
  content is immutable and addressed by hash; publishing moves a pointer

    Commands use .quilzo in the current directory. Pass --root DIR to use another.

  3. Make yourself an administrator and get a sign-in token

    Access is granted before any credential exists. The policy names who may do what, and a token only proves you are one of those people.

    quilzo auth grant you admin
quilzo token issue you --principal you --role admin
    granted admin to you on /
  you can now: view, edit-draft, publish, rollback, grant, manage-tokens on /

    The token is printed once, and only its hash is stored. Save it to ~/.quilzo/token with mode 0600 and the command line uses it from then on; the command line also accepts --token or QUILZO_TOKEN. If you lose it, issue another and revoke the first with quilzo token revoke ID.

  4. Load something to work on (optional)

    quilzo demo installs Marginalia, a small paper shop: pages, a product catalogue as structured records, images, listings and forms. Every screenshot in this manual was taken from it.

    quilzo demo
    Marginalia is installed. A paper shop: products as structured records, a catalogue a machine can read, …
  11 page(s), 15 record(s), 12 image(s), 7 listing(s), 2 form(s)

  5. Open the admin and sign in

    The admin listens on loopback by default. --open opens it in your browser.

    quilzo serve --open

    Paste the token from step 3. Once you are in, you can add a passkey under Administration › Passkeys or connect single sign-on (see Single sign-on).

Find your way around the admin

The Get started screen opens the first time you sign in. Its checklist ticks each step when the store shows it is done, not when you click past it.

The menu on the left groups the screens: Content, Release, Assurance, Security operations, Administration and Reference. To jump anywhere, press Ctrl K (⌘ K on a Mac) and type: Find covers every screen, page, setting and content type.

Every screen has a Help link in its footer that opens the guide for that screen. What you may do, your sessions, and how the admin looks to you are under Reference › You.

Run your first agent

  1. Declare one

    A retrieval agent answers questions from published content and cannot write anything. It is where most agents should start.

    quilzo agent new help-desk --kind retrieval
    declared help-desk (retrieval)
  Answer questions using published content only.
  capabilities  read_page, list_pages, search_pages, similar_pages
  autonomy      propose

  2. Run it without a model

    With no model, a run tries each capability once. It shows what the store answers and what the gate allows, which makes it a cheap first test.

    quilzo agent run help-desk

  3. Connect a model and ask it something

    Point Quilzo at any OpenAI-compatible endpoint. A local model through Ollama is enough; nothing leaves the machine.

    export QUILZO_MODEL_URL=http://127.0.0.1:11434/v1
export QUILZO_MODEL=llama3.1
quilzo agent run --model help-desk "Can I return an opened bottle of ink?"

    The model picks each step from the agent's declared capabilities and cannot add to them. Every run is kept, and you can read it step by step:

    quilzo agent runs
quilzo agent trace RUN
    help-desk  complete  Can I return an opened bottle of ink?
   1  search_pages   done   1 page(s) match, best first: returns
   2  read_page      done   body: Thirty days, unused, and we pay the postage back. Ink is the exception…
   3  finished       done   done

Publish the site

The public site is a second process with no editing surface, so the part facing the internet cannot change anything.

quilzo site --addr 127.0.0.1:8081

Three ways in, one set of rules

Everything is reachable from the admin, from the command line (quilzo help lists every command, and each one takes --json), and from the agent interface over MCP. A rule enforced in one of them is enforced in all three, because they share one code path.
