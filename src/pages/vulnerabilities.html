Not part of Quilzo. Finding and ranking the flaws in your other systems, scanning their dependencies and following each fix to the end belong to the vulnerability management your organisation already runs. Quilzo answers one question in that area: what is known to be wrong with Quilzo itself.

Check this build

Quilzo has no third-party dependencies, so every known flaw that can reach it is in the Go standard library it was built with. quilzo self check reads the Go vulnerability database against what is actually linked into the running binary, offline, and decides each advisory that concerns its Go:

DecisionWhen
Not reachableWhat the advisory names is not linked into this binary, so nothing can reach it.
ContainedIt is known to be exploited, and only features that can be turned off reach it.
Upgrade GoWhat every server runs uses it, or it is not known to be exploited: a person decides, and upgrades Go.

The admin runs the same check every hour, and a flaw it finds in this build is told once a day, not at every check. Security › Inventory shows it under Known flaws in this build, with the date of the database and whether the binary is the one it says it is, which quilzo self verify also answers. quilzo self vex writes an OpenVEX statement for each advisory.

Keep the database current

A snapshot of the database is embedded at release, and nothing is fetched by itself. Download a newer one, and CISA's catalogue of Known Exploited Vulnerabilities, wherever you can, and give them to Quilzo:

quilzo self update vulndb.zip                          # from https://vuln.go.dev/vulndb.zip
quilzo self kev known_exploited_vulnerabilities.json   # CISA's KEV catalogue, as JSON
quilzo self check

Each is read on the machine and written to the audit log. A database more than a month old is flagged on Inventory and by self check, because a check against an old list is a clean bill of health that stopped being true.

Only the catalogue says a flaw is being exploited, and only then is it contained at once. So self check says when no catalogue has been given, when it cannot be read and when it is more than a month old, and the security posture reports the same as self.kev-missing. Without it, such a flaw waits for a person to upgrade Go.

When a flaw turns a feature off

When the catalogue says a flaw is being exploited, and only features a site can do without reach it, such as uploads, forms, import, the chatbots or the API, the shield's self-exposure playbook turns those features off for a day. It tells the security contact, and writes a request to open a case into the audit log. Any other flaw that reaches this build is one to upgrade Go for: the self-flaw playbook tells the security contact and asks for a case, then reminds them each day until Go is upgraded. quilzo shield lift ends a protection early.
